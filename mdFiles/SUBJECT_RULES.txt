-------------------------------------------------------------------------------
 0. HARD RULES (instant-fail if broken)
-------------------------------------------------------------------------------
[*] Language: C++ 98 ONLY. Compile with -Wall -Wextra -Werror -std=c++98.
    No C++11+ (auto, nullptr, range-for, <thread>, lambdas, unordered_map, ...).
[*] No external libraries. No Boost. Standard C++98 lib + POSIX only.
[*] The server must NEVER block. All fds are non-blocking.
[*] ONE and only ONE poll() (or select/epoll/kqueue) for ALL I/O — listen
    sockets + client sockets + CGI pipes — both read AND write readiness.
[*] You may NEVER read/recv or write/send on any fd without it first being
    reported ready by poll(). Doing so = grade 0.
[*] Checking errno AFTER a read/recv OR write/send is STRICTLY FORBIDDEN.
    (Decide what to do from the return value alone: >0 data, 0 = peer closed,
     <0 = treat as error and drop the client — do NOT inspect errno.)
[*] fork() is allowed ONLY for CGI. Nowhere else.
[*] The server must never crash — not on malformed input, not under stress,
    not on client disconnect mid-request. No memory leaks.
[*] A request to a nonexistent CGI / a hanging CGI must not hang the server.

-------------------------------------------------------------------------------
 1. ALLOWED EXTERNAL FUNCTIONS  (the ONLY syscalls/libc we may use)
-------------------------------------------------------------------------------
Process / exec:
    execve, fork, waitpid, kill, signal, chdir, access

Pipes / fds:
    pipe, dup, dup2, close, read, write, fcntl (RESTRICTED — see below)

Sockets / network:
    socket, socketpair, accept, listen, bind, connect,
    send, recv, setsockopt, getsockname, getprotobyname,
    getaddrinfo, freeaddrinfo

Byte order:
    htons, htonl, ntohs, ntohl

Multiplexing (pick ONE family):
    select  (+ FD_SET, FD_CLR, FD_ISSET, FD_ZERO)
    poll
    epoll_create, epoll_ctl, epoll_wait
    kqueue, kevent

Filesystem / dirs:
    open, stat, opendir, readdir, closedir

Errors / strings:
    errno (use OK — but NOT to be checked after read/write), strerror,
    gai_strerror

NOTE on fcntl: in this project it may be used in EXACTLY one way:
        fcntl(fd, F_SETFL, O_NONBLOCK);
    Any other flag / any other use of fcntl is forbidden.

    KNOWN DISCREPANCY (recorded 2026-08-01, not resolved): the subject PDF
    lists the allowed flags as "F_SETFL, O_NONBLOCK and FD_CLOEXEC", which
    would permit close-on-exec. That listing is self-inconsistent — FD_CLOEXEC
    is set with F_SETFD, not F_SETFL — so an evaluator could reasonably read it
    either way, and we do not rely on the permissive reading.

    Consequence for CGI: the fd-inheritance problem (a forked child inheriting
    every listen and client socket) is solved by having the CHILD close them
    explicitly after fork, which needs no ruling from anyone. Do not introduce
    FD_CLOEXEC to shortcut this without settling the question first.

Standard C++98 library (iostream, string, vector, map, sstream, fstream,
algorithm, cctype, cstdlib, ctime, cstring...) is fine — it is not an
"external library".

 2. FORBIDDEN / NOT-ON-THE-LIST  (common traps — do NOT use)
-------------------------------------------------------------------------------
[X] inet_pton / inet_ntop / inet_addr / inet_ntoa
        -> NOT allowed. To fill a sockaddr_in:
             - bind-all:   addr.sin_addr.s_addr = htonl(INADDR_ANY);   // 0.0.0.0
             - specific IP: use getaddrinfo() (allowed) and copy the result,
               OR parse the dotted quad yourself and build the 32-bit value.
        -> To print a client IP: derive it from the sockaddr you already have
           (getpeername/getsockname are NOT both listed — getsockname is;
            getpeername is NOT) or skip printing the IP. Simplest: don't
           pretty-print the peer IP, or reconstruct it manually from
           ntohl(addr.sin_addr.s_addr).
[X] unlink / remove(2) / rmdir  -> NOT listed. The table has NO deletion
                         syscall at all, yet DELETE is mandatory. Use
                         std::remove() from <cstdio>: it is ISO C++98 (27.8.2),
                         so it rides on the standard library, not on the
                         External Function table — the same cover as
                         memset/atoi/time. See DeleteHandler.cpp.
[X] _exit             -> NOT listed. std::exit IS (<cstdlib>, C++98). See the
                         OPEN item in section 5 before touching the CGI child.
[X] perror            -> NOT listed. Use: std::cerr << msg << ": "
                                       << strerror(errno) << std::endl;
                         (only after non-read/write calls, e.g. socket/bind).
[X] bzero             -> use memset (memset is std C, accepted) or value-init.
[X] gethostbyname     -> use getaddrinfo.
[X] sprintf/snprintf for building responses -> use std::ostringstream.
[X] malloc/free/new-without-delete leaks    -> RAII / clean up in destructors.
[X] Any check of errno after recv/send/read/write.
[X] Multiple poll()/select() loops. Threads.

-------------------------------------------------------------------------------
 3. ARCHITECTURE RULES THE EVALUATOR CHECKS
-------------------------------------------------------------------------------
- Single-threaded, single event loop.
- Every socket/pipe set non-blocking with fcntl(fd, F_SETFL, O_NONBLOCK).
- SO_REUSEADDR on listen sockets (setsockopt) so restart doesn't fail.
- Partial reads: accumulate into a per-client input buffer; the parser is a
  re-entrant state machine (picks up where it left off).
- Partial writes: track bytes_sent; register POLLOUT; keep draining.
- Client closes (recv == 0): clean up state, close fd, remove from poll set,
  never crash.
- POLLHUP / POLLERR / POLLNVAL handled -> drop that client.
- CGI: child stdout pipe is ALSO a poll()-managed non-blocking fd. Body piped
  to child stdin. waitpid(WNOHANG) to reap. chdir() to script dir before
  execve(). Only fork() here.
- Config: define the grammar precisely; a missing/invalid field must fail
  closed (reject the config), not silently corrupt.

-------------------------------------------------------------------------------
 4. STATUS CODES TO COVER
-------------------------------------------------------------------------------
200 OK, 201 Created, 204 No Content,
301 Moved Permanently, 302 Found,
400 Bad Request, 403 Forbidden, 404 Not Found, 405 Method Not Allowed,
408 Request Timeout, 413 Content Too Large / Payload Too Large,
431 Request Header Fields Too Large,
500 Internal Server Error, 501 Not Implemented,
502 Bad Gateway, 504 Gateway Timeout, 505 HTTP Version Not Supported.

  502 — the CGI script produced nothing usable: it exited without emitting a
        header block, or its pipe failed. Emitted by _handleCgiPipeRead().
  504 — a CGI script exceeded CGI_TIMEOUT_SEC (30s) and was SIGKILLed before
        emitting any header. Implemented in 485e110 and measured: a script
        containing sleep(9999) returns 504 with the server still serving.
        Once headers are already on the wire a status code can no longer be
        sent, so a timeout there ends as a withheld terminator instead — the
        truncation signal, not a code.
  505 — request line named a version we do not speak. The parser seeds
        request.status with it; _advanceRequest forwards that code rather
        than a blanket 400.
  431 — header section exceeded MAX_HEADER_BYTES before a blank line.

CGI AUDIT (added 2026-08-01, after dd0b519 + cb302fd)
COMPLIANT:
  - one poll() covers listen + client + CGI pipe fds; pipe registered in
    _rebuildPollFds(), dispatched in _handlePollEvents()
  - parent's pipe read end non-blocking via the exact allowed fcntl form
  - no errno inspected after the pipe read; >0 / 0 / <0 only
  - child ends in execve or _exit(1) — never a return
    ^ CORRECTED 2026-08-14: this line used to read "never exit()" and marked
      _exit as compliant. _exit is NOT in the External Function table either;
      exit() is reachable as std::exit (<cstdlib>, C++98). See the OPEN item.
  - waitpid(WNOHANG) on every path driven by the script's own pace. The ONE
    deliberate exception is _killCgi(): after SIGKILL it waits blocking, which
    is safe because SIGKILL cannot be caught or ignored, so the wait is bounded
    by scheduler latency rather than by the script. WNOHANG there would leave
    the pid behind on the client-death path, where no Client remains to carry
    it and no sweep can retry -- a zombie with no owner. Known caveat: a child
    in uninterruptible sleep (D state) defers even SIGKILL; accepted knowingly
  - parent closes its copy of the child's write end immediately after fork,
    so EOF on the read end is reachable at all
  - POLLHUP is not treated as terminal: the read runs first and only a
    return of 0 ends the response (avoids truncating fast scripts)
  - fork() appears exactly once in the codebase, in _startCgi()
  - interpreter comes from LocationConfig::cgi_ext; nothing hardcoded
  - framing chosen by request version: 1.1 -> chunked (self-delimiting, may
    keep-alive), 1.0 -> close-delimited and keep_alive forced false

OPEN:
  - HttpParser accepts whitespace before the colon. `Content-Length : 5` parses
    as a valid Content-Length and the request answers 200. RFC 7230 §3.2.4 says
    a server MUST reject it, and the reason is the same one behind the CL+TE
    rejection the parser already does: if a proxy in front of us disagrees about
    whether that line is a header, the gap is a request-smuggling primitive.
    B's file (C reported it; B fixed the other three findings but not this one).
    Verified still open against the merged tree on 2026-08-04.
    The other three are CLOSED and confirmed by probe: conflicting duplicate
    Content-Length -> 400, empty header name -> 400, CL+TE together -> 400,
    and an IDENTICAL duplicate Content-Length is still accepted (correct — the
    RFC only bars conflicting values).

  - src/main.cpp is tracked but treated as local-only. .gitignore lists it under
    "each teammate keeps their own to avoid merge conflicts", but git ignores
    that rule for already-tracked files, so a teammate's local edit is committed
    like any other. That is exactly how main() got commented out and pushed.
    Same trap applies to the Makefile, also listed-but-tracked.
    Fix is a team decision, so it is NOT being made unilaterally here. Either
    untrack it (`git rm --cached src/main.cpp`) and accept that the repo no
    longer builds from a clean clone, or drop it from .gitignore and agree that
    everyone shares one entry point. It cannot stay as it is.
    A guard that would have caught it regardless: `make test` on the merged tree
    fails loudly, which is why it now exists.

  - HEAD: half done, blocked on Member C for the rest.
    A's half is CLOSED — the framing point suppresses the body while keeping the
    Content-Length the GET would have sent (Server.cpp, ResponseBuilder call
    site). Verified live: `HEAD /` returns Content-Length: 101 with 0 body
    bytes, GET unaffected.
    C's half is OPEN — Dispatcher.cpp:56-64 routes only GET/DELETE/POST, so
    HEAD still falls through to 501. One line: route HEAD to GetHandler, i.e.
    `if (request.method == "GET" || request.method == "HEAD")`. The allow-list
    check above it must keep seeing the real method, so this cannot be done by
    rewriting HEAD->GET before dispatch — a location that permits GET but not
    HEAD has to stay a 405.
    FALLBACK if it does not land before the defense: drop HEAD from
    config/default.conf:19,50 rather than ship a config that advertises a
    method we answer 501 to. HEAD is not required by the subject.

  - PUT is accepted by Config.cpp:220 as a valid allowed_methods token but is
    advertised in no config and implemented nowhere. Same 501 trap as HEAD if
    an evaluator writes it into their own config.

  - _exit(1) in the CGI child: Server.cpp:2046, 2047, 2118, 2138. Not in the
    External Function table. std::exit (<cstdlib>) is C++98 standard library
    and so carries the same cover std::remove does — but swapping it in is NOT
    a free rename, which is why this is OPEN rather than fixed:

      exit() runs atexit handlers and FLUSHES the stdio/iostream buffers the
      child inherited from the parent across fork(). The child has already
      dup2'd its stdout onto the CGI pipe, so anything the parent had buffered
      in std::cout at fork time gets flushed INTO the CGI response body — a
      corrupted response that only appears when the parent happens to have
      unflushed output, i.e. intermittently and never under a debugger.

    If we take this: flush std::cout and std::cerr immediately BEFORE fork(),
    then use std::exit(1) in the child. Verify by logging to std::cout without
    std::endl right before a CGI request and confirming the body is clean.
    Decide as a team — unlike unlink, there is a real behavioural risk here and
    _exit is defensible as "the POSIX half of a fork/exec pair the table does
    license". Whichever way it goes, record it here.
